# Telegram LLM Bot

Telegram-бот на Python поверх локальной языковой модели [Ollama](https://ollama.com),
превращённый в минимального автономного агента: модель не только отвечает текстом,
но и сама выполняет консольные команды на машине пользователя (инструмент exec)
и пользуется скиллами — markdown-файлами с готовыми инструкциями для типовых задач.

Возможности:

- **чат-сессия** — история каждого чата хранится на диске и подмешивается к
  запросу: бот помнит контекст диалога и переживает перезапуск;
- **агентный цикл** — модель либо даёт финальный ответ, либо вызывает exec,
  видит результат и продолжает; лимит шагов защищает от зацикливания, при
  исчерпании пользователь получает честное сообщение об остановке;
- **инструмент exec** — одна shell-команда из корня проекта; модель получает
  exit code, stdout и stderr; зависшая команда обрывается по таймауту;
- **скиллы** — каталог `skills/<имя>/SKILL.md`: системный промпт содержит только
  индекс (имя + краткое описание), полный текст модель читает сама через exec.
  Новый скилл добавляется файлом, без правки кода;
- **/new** — команда начинает новую чат-сессию: старая история отбрасывается;
- выполняемые команды в чат не выводятся (внутренняя кухня агента);
  длинные ответы разбиваются на несколько сообщений по границам строк.

## Архитектура

```text
Telegram (aiogram adapter)                сплиттер длинных ответов
        ↓
ApplicationService (use case: ProcessUserMessage) ←→ ChatSessionStore (.data/chats/<chat_id>.jsonl)
        ↓                                              + окно истории, блокировка на чат
AgentLoop (агентный цикл) —— Tool: ExecTool (shell в корне проекта, таймаут, обрезка вывода)
        |                     индекс скиллов в системном промпте
        ↓
InferenceProvider (Protocol)
        ↓
OllamaInferenceProvider (adapter, httpx; нативный протокол tool-calls)
        ↓
Ollama /api/chat (non-streaming)
```

Ключевые принципы:

- слои общаются только через типизированные контракты:
  `Telegram ≠ Application ≠ Agent ≠ Inference ≠ Ollama`;
- Telegram-слой не знает про Ollama; application-слой — про aiogram; агентный
  цикл зависит от протокола `InferenceProvider`, а не от адаптера Ollama;
- исполнитель команд (`ExecTool`) отделён от цикла: цикл знает инструмент по
  `ToolSpec` (имя, параметры), как именно выполняется команда — его дело;
- никакого глобального изменяемого состояния: все объекты создаются в
  composition root (`src/bot/main.py`) и внедряются явно через конструкторы;
- семантические идентификаторы — `typing.NewType`, внутренние модели —
  неизменяемые `dataclass(frozen=True)`, роли — `StrEnum`;
- ошибки инфраструктуры маппятся в прикладные исключения и не попадают
  к пользователю в исходном виде.

Подробнее о границах слоёв — `docs/architecture.md`; решение осознанно оставить
exec без ограничений на команды зафиксировано в `docs/adr/0001-exec-tool-unrestricted.md`.

## Чат-сессии

Одна чат-сессия — один JSONL-файл `.data/chats/<chat_id>.jsonl`, append-only:
строка файла — одно сообщение диалога «пользователь ↔ финальный ответ».
Вызовы инструментов и их результаты в сессию не пишутся — они живут только
внутри одного агентного запуска (результат инструмента, особенно ошибка,
в истории сбивает модель на следующих ответах). Каталог `.data/` исключён
из git. Системный промпт на диске не живёт — собирается заново при каждом
запросе. В запрос уходит окно последних сообщений сессии
(`AGENT_HISTORY_MAX_MESSAGES`). Сообщения одного чата обрабатываются строго
последовательно, разные чаты — параллельно.

## Скиллы

Раскладка — один каталог на скилл: `skills/<имя>/SKILL.md`. Шапка файла — YAML
frontmatter с полями `name` и `description`; запасной вариант без frontmatter —
строка `Description:` (имя тогда берётся из имени каталога). Индекс собирается
при каждом запуске бота и попадает в системный промпт вместе с правилами цикла;
полный текст скилла модель читает сама через exec (`cat skills/…`). В репозитории
есть пример — скилл `weather`: сводка погоды через публичный wttr.in.

## Требования

- Python 3.13
- [uv](https://docs.astral.sh/uv/)
- Запущенный [Ollama](https://ollama.com) с моделью:

```bash
ollama pull qwen3:1.7b
# альтернатива:
ollama pull tinyllama
```

## Конфигурация

Скопируйте `env.example` в `.env` и заполните токен бота (получите у @BotFather):

```bash
cp env.example .env
```

| Переменная | По умолчанию | Описание |
|---|---|---|
| `TELEGRAM_BOT_TOKEN` | — (обязательная) | токен бота; хранится как `SecretStr`, не логируется |
| `OLLAMA_BASE_URL` | `http://localhost:11434` | адрес Ollama |
| `OLLAMA_MODEL` | `qwen3:1.7b` | модель инференса |
| `OLLAMA_THINK` | `false` | режим размышлений модели (`think` в запросе к Ollama); reasoning-моделям вроде qwen3 нужен `true` — без него возможны пустые ответы на многошаговых задачах |
| `AGENT_MAX_STEPS` | `10` | лимит шагов агентного цикла (один шаг = один ответ модели); защита от зацикливания |
| `AGENT_HISTORY_MAX_MESSAGES` | `20` | окно истории чат-сессии: сколько последних сообщений уходит в запрос |
| `AGENT_EXEC_TIMEOUT_SECONDS` | `60` | таймаут одной команды exec; зависшая команда убивается вместе с группой процессов |
| `AGENT_EXEC_MAX_OUTPUT_CHARS` | `4000` | суммарная обрезка вывода команды (exit code + stdout + stderr) до этого числа символов |
| `AGENT_SKILLS_DIRECTORY` | `skills` | каталог скиллов для индекса |
| `TELEGRAM_ALLOWED_CHAT_IDS` | пусто | allowlist чатов через запятую; пусто — бот отвечает всем, заполнен — чужие чаты молча игнорируются |
| `OLLAMA_TIMEOUT_SECONDS` | `120` | таймаут запроса к Ollama |
| `TELEGRAM_TIMEOUT_SECONDS` | `30` | таймаут запросов к Telegram API |
| `LOG_LEVEL` | `INFO` | уровень логирования |
| `LOG_FORMAT` | `console` | `console` или `json` |

Валидация конфигурации — pydantic-settings, fail fast на старте: неверное значение
любой переменной падает с ошибкой валидации ещё до запуска поллинга.

## Безопасность

По умолчанию агент выполняет произвольные shell-команды без allowlist команд —
это осознанное решение для личной машины (см. ADR-0001). Сдерживающие механизмы:
таймаут команды, обрезка вывода, лимит шагов цикла. Главный внешний риск —
чужие люди в Telegram — закрывается allowlist'ом чатов (`TELEGRAM_ALLOWED_CHAT_IDS`):
заполнив его одним своим chat id, вы оставляете доступ только себе.
Команды в логах не пишутся (логируются только метрики), но сохраняются в
локальную JSONL-сессию чата.

## Запуск

```bash
uv sync                 # создать venv и установить зависимости (uv.lock фиксирует граф)
uv run python -m bot.main
```

## Проверки

```bash
uv run ty check                  # проверка типов
uv run ruff check .              # линтер
uv run ruff format --check .     # форматирование
uv run pytest                    # тесты (Ollama и Telegram не требуются)
```

## Структура проекта

```text
src/bot/
├── main.py              # composition root: сборка графа зависимостей, поллинг
├── config/settings.py   # pydantic-settings: переменные окружения и .env
├── domain/
│   ├── ids.py           # семантические идентификаторы (NewType)
│   ├── messages.py      # MessageRole, InferenceMessage
│   └── tools.py         # ToolSpec / ToolCall / ToolResult — контракт инструментов
├── agent/
│   ├── loop.py          # агентный цикл: до финального ответа или лимита шагов
│   ├── tools.py         # Protocol Tool — что должен уметь исполнитель
│   ├── exec.py          # ExecTool: shell-команда, таймаут, обрезка вывода
│   ├── skills.py        # индекс скиллов из каталога (чистые функции)
│   ├── prompts.py       # системный промпт + секция индекса скиллов
│   └── progress.py      # Protocol AgentProgress — отображение шагов
├── sessions/
│   ├── store.py         # ChatSessionStore: JSONL-файл на чат, append-only
│   └── window.py        # окно последних сообщений истории
├── application/
│   ├── errors.py        # прикладные исключения
│   ├── models.py        # UserMessageRequest / UserMessageResponse
│   └── service.py       # ApplicationService — ProcessUserMessage, блокировка на чат
├── inference/
│   ├── models.py        # InferenceRequest / InferenceResponse
│   ├── provider.py      # Protocol InferenceProvider
│   └── ollama.py        # адаптер Ollama (httpx + Pydantic на границе JSON)
└── telegram/
    ├── handlers.py      # aiogram-обработчики (/start, /new, текст)
    ├── mapper.py        # aiogram Message → UserMessageRequest
    └── splitter.py      # разбивка длинных ответов на части по границам строк

skills/weather/SKILL.md  # первый скилл: погода через wttr.in
.data/chats/             # чат-сессии <chat_id>.jsonl (исключён из git)
tests/
├── unit/                # сервис, цикл, exec, скиллы, сессии, адаптер Ollama, хендлеры
└── integration/         # полный цикл Telegram → приложение → агент (без сети)
```

## Логирование

`structlog`, настройка выполняется в composition root, логгеры внедряются через
конструкторы. В логах — только идентификаторы и метрики (`request_id`, `model`,
`steps`, `duration_ms`, `status`), но не содержимое сообщений и команд
пользователя и не секреты.
