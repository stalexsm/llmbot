# Архитектура: границы слоёв

Центральный принцип: `Telegram ≠ Application ≠ Agent ≠ Inference ≠ Ollama`.
Каждая граница изолирована и общается через типизированные контракты.

## Правила границ слоёв

- **Telegram-адаптер** (`src/bot/telegram/`): маппинг Telegram ↔ application DTO,
  вызов `ApplicationService`, обработка Telegram-ошибок. Этот слой не знает про
  Ollama ничего: ни URL, ни JSON, ни класса провайдера, ни логики инференса.
- **ApplicationService** (`src/bot/application/`): принимает типизированный вход,
  вызывает агентный цикл, возвращает типизированный ответ. Не знает объекты
  Telegram API и JSON Ollama.
- **InferenceProvider** (`src/bot/inference/provider.py`) — `typing.Protocol`;
  приложение зависит только от протокола. Новый провайдер добавляется без
  изменений application- и telegram-слоёв; замена Ollama не трогает их.
- **OllamaInferenceProvider** (`src/bot/inference/ollama.py`): HTTP-обмен,
  сериализация/парсинг, валидация ответа, таймауты, маппинг инфраструктурных
  ошибок на application-исключения. Без Telegram-логики. `httpx.AsyncClient`
  инжектится извне и переиспользуется всё время жизни — клиент на каждый запрос
  не создаётся.

## Состояние и внедрение зависимостей

- Глобальное изменяемое runtime-состояние на уровне модуля запрещено:
  `bot = Bot(...)`, `settings = Settings(...)`, провайдеры и сервисы как
  module-level инстансы. Разрешены определения — классы, функции, константы,
  `NewType`, `Protocol`.
- Зависимости внедряются явно, через конструкторы. Компонент создаёт свои
  инфраструктурные зависимости только снаружи — сам себе их не конструирует
  (`ApplicationService` не создаёт `OllamaInferenceProvider`).
- DI-контейнер (Dishka) не используется: сборка зависимостей ручная, в
  композиционном корне. Контейнер — отдельное будущее решение, и его ввод не
  должен требовать изменений domain/application-контрактов.
- Композиционный корень — `src/bot/main.py` (`run()`):
  Settings → httpx-клиент → OllamaInferenceProvider → ExecTool → AgentLoop →
  ApplicationService → Bot/Dispatcher → polling. Владение жизненным циклом
  явное: HTTP-клиент и сессия бота закрываются в `finally`.

## Ошибки

- Инфраструктурные ошибки остаются вне application-слоя: адаптер Ollama
  маппит HTTP/сеть/таймауты на application-исключения (`InferenceError`,
  `InferenceTimeoutError`, `InferenceUnavailableError`).
- Telegram-слой превращает application-ошибки в безопасные сообщения.
  Пользователь получает raw-исключения, стеки, URL и детали инфраструктуры
  только через безопасный текст-заглушку — никогда напрямую.
