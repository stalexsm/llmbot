# Runtime: конфигурация, логирование, таймауты

## Сеть

- httpx-клиент Ollama создаётся в композиционном корне с `trust_env=False`:
  запросы идут в локальный Ollama напрямую и не подхватывают прокси из
  переменных окружения или системных настроек macOS — иначе трафик к
  localhost уходит в локальный прокси-клиент и рвётся.

## Конфигурация

- Конфигурация — `pydantic-settings` из env/`.env`; обязательный
  `TELEGRAM_BOT_TOKEN`. Валидация на старте, fail fast при отсутствии/невалидности.
- Токен живёт только в env/`.env`: не в коде, не в логах, не в Git.
  `.env` в `.gitignore`; вместо него коммитится `env.example`.
- Агентные лимиты — тоже часть `Settings` и приходят из env: лимит шагов
  цикла (`AGENT_MAX_STEPS`, 10), окно истории чат-сессии
  (`AGENT_HISTORY_MAX_MESSAGES`, 20), компакция старших tool-выводов в
  агентном цикле: выводы шагов старше последних K схлопываются в сигнатуру
  «команда → ok/ошибка», записанная сессия не меняется
  (`AGENT_COMPACTION_KEEP_STEPS`, 3; 0 — выключено), таймаут команды exec
  (`AGENT_EXEC_TIMEOUT_SECONDS`, 60), обрезка вывода команды
  (`AGENT_EXEC_MAX_OUTPUT_CHARS`, 4000; вывод перед обрезкой чистится
  от ANSI-кодов и прогресс-шума, при превышении лимита сохраняются голова
  и хвост, середина схлопывается маркером с числом пропущенных символов),
  каталог скиллов
  (`AGENT_SKILLS_DIRECTORY`, `skills`), allowlist чатов
  (`TELEGRAM_ALLOWED_CHAT_IDS`, пусто — бот отвечает всем).
- Системный промпт хранится сжатым в коде (`src/bot/agent/prompts.py`,
  `skills.py`): он уходит в каждый шаг каждого запуска, поэтому без
  конфигурации. Гард от раздувания и от чрезмерного сжатия — юнит-тесты
  `TestPromptBudget` (бюджет символов и семантические якоря); обоснование
  и цифры — `docs/token-optimization-report.md`.
- Режим размышлений модели (`OLLAMA_THINK`, по умолчанию `false`) включает
  в запросе к `/api/chat` флаг `think`. Reasoning-моделям вроде qwen3 нужен
  `true`: без размышлений они могут молча выдавать пустой ответ на
  многошаговых инструментальных задачах; служебные размышления вырезаются
  из ответа адаптером.
- Окно контекста на запрос (`OLLAMA_NUM_CTX`, по умолчанию `8192`) уходит
  в `/api/chat` как `options.num_ctx` и перекрывает дефолт сервера Ollama
  (`OLLAMA_CONTEXT_LENGTH`, обычно 4096). Размер окна напрямую влияет на
  память под KV-кэш.
- БД чат-сессий фиксирована кодом — `.data/chats.db` (ADR-0003) и исключена
  из Git: в свежем клоне её нет. Схема — только миграции alembic: новая
  ревизия создаётся `uv run alembic revision --autogenerate -m "..." --rev-id <имя>`
  (метаданные — `src/bot/sessions/schema.py`), композиционный корень применяет
  миграции на старте до первой операции. Старые JSONL-файлы `.data/chats/`
  не импортируются и не трогаются.
- Метрики токенов пишутся в `.data/metrics/events.jsonl` (тоже вне Git,
  append-only, создаётся при первой записи). Цены input/output за 1M токенов
  приходят из env (`METRICS_INPUT_PRICE_PER_MTOK`,
  `METRICS_OUTPUT_PRICE_PER_MTOK`), по умолчанию 0 — стоимость считается
  нулевой. События содержат только счётчики и идентификаторы: ни содержимого
  сообщений, ни команд, ни ответов модели; сбой хранилища метрик работу
  бота не рвёт.

## Логирование

- Логирование — `structlog`, структурированные события. Поля:
  `event`, `request_id`, `component`, `status`, `duration_ms`, `model`, `error`.
- Не логируются: токен, auth-заголовки, API-ключи, полные сообщения
  пользователя, полные ответы LLM, выполняемые агентом команды.
- Логгер конфигурируется один раз в композиционном корне и инжектится в
  компоненты; глобальных runtime-логгеров нет. `RequestId` передаётся явно как
  часть данных операции и пользователю не показывается.

## Таймауты и RequestId

- Все внешние сетевые операции (Telegram API, Ollama HTTP) — с явными
  таймаутами; значения таймаутов живут в `Settings`.
- Каждое обработанное сообщение получает уникальный `RequestId`
  (`RequestId(str(uuid4()))`) — для логирования, корреляции и трассировки.
