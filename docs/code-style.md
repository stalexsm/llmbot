# Стиль кода: типизация и модели

- Строгая статическая типизация: все публичные функции и методы аннотированы;
  `uv run ty check` проходит без ошибок.
- `Any`, `dict[str, Any]`, `cast(...)` — только на оправданной внешней границе;
  в domain/application-контракты не протекают.
- Каждый семантически отдельный ID — собственный `NewType`
  (`TelegramUserId`, `TelegramChatId`, `RequestId`, `ModelId`, …;
  см. `src/bot/domain/ids.py`). Голые `int`/`str` в контрактах приложения и
  домена не используются; новые сущности (`AgentId`, `ToolId`) тоже получают
  свой `NewType`.
- Внутренние модели — иммутабельные dataclasses: `@dataclass(frozen=True)`,
  кортежи вместо списков. Сырые словари как внутренний протокол не используются.
- Pydantic — только на внешних и конфигурационных границах
  (`pydantic-settings`); внутрь приложения данные входят как dataclasses,
  конвертация происходит на границе.
- Интерфейсы — `typing.Protocol`; перечисления — `enum.StrEnum`
  (например `MessageRole`).
