# ADR-0001: Инструмент exec без ограничений на команды

- Статус: принято (issue #11, мигрировано из локального трекера)
- Дата: 2026-08-26

## Контекст

Основная спецификация (`docs/homework1-specification.md`, §25) требует для будущего
агента явной проработки границ безопасности, включая «нет неограниченного
shell-исполнения по умолчанию». Issue #11 намеренно вводит инструмент exec как
единственный инструмент агента и не запрашивает allowlist команд.

## Решение

Для минимального агента exec выполняет произвольную консольную команду в shell
пользователя (одна строка, рабочий каталог — корень проекта) без allowlist
команд и без ограничений файловой системы и сети.

Обоснование: агент живёт на личной машине пользователя, выполняет его же
запросы; allowlist команд сломал бы главную ценность агента (произвольные
CLI-задачи и чтение скиллов в issue #12).

Сдерживающие механизмы реализованы сразу:

- таймаут выполнения (60 с по умолчанию, `AGENT_EXEC_TIMEOUT_SECONDS`) с
  убийством группы процессов;
- обрезка вывода до ~4000 символов (`AGENT_EXEC_MAX_OUTPUT_CHARS`);
- лимит шагов цикла (10 по умолчанию, `AGENT_MAX_STEPS`);
- команды не логируются (контент в логах запрещён §20); диалог пользователя
  с агентом сохраняется в локальную чат-сессию (SQLite-хранилище, ADR-0003),
  сами команды и их вывод в сессию не пишутся.

## Последствия

- Разделение «командного allowlist» отложено; если потребуется — отдельный
  ADR с учётом скиллов.
- Allowlist чатов (кто может пользоваться агентом) — отдельное решение,
  запланированное issue #13; он закрывает главный внешний риск: чужие люди
  в Telegram, получившие доступ к боту.
- Изменение решения (изоляция, контейнер, выделенный сервис) требует нового
  ADR и пересмотра этого.
