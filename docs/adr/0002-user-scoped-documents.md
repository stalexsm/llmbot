# ADR-0002: Документы изолированы по пользователю Telegram

- Статус: принято (домашнее задание «RAG для AI-агента», §10 «Изоляция пользователей»)
- Дата: 2026-09-09

## Контекст

Задание требует, чтобы документы одного пользователя никогда не использовались
при ответе другому. Вся существующая система — чат-сессии, allowlist, блокировка
обработки — ключуется по `TelegramChatId`; понятия «пользователь» в домене нет.
Загрузка документа и поиск по нему могли бы использовать тот же chat-скоуп.

## Решение

Владелец документа — пользователь Telegram (`TelegramUserId`, NewType поверх
`from_user.id`), а не чат. Поиск `search_documents` всегда фильтруется по
владельцу; `/documents` и `/delete` работают с корпусом владельца. Чат-сессии,
allowlist и блокировка обработки остаются chat-scoped — у системы появляются два
независимых идентификатора.

Обоснование: в групповом чате chat-scoped владелец смешал бы корпуса участников —
поиск одного отвечал бы документами другого. Изоляция по пользователю так же
прямее закрывает демонстрацию «двух пользователей» на защите.

## Последствия

- В домене второй NewType-идентификатор (`TelegramUserId`); на границе Telegram-
  слоя `from_user.id` обязателен (у сообщений без автора документ не принимается).
- Инструмент агента не может узнать владельца из `RequestId` — скоуп доходит до
  инструментов как явный контекст выполнения (расширение контракта `Tool`).
- Изоляция — обязательный тест: поиск владельца A никогда не возвращает чанки
  владельца B.
