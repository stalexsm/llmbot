# 02: RAG-ядро: txt → чанки → эмбеддинги → rag-БД → поиск

**What to build:** узкий полный путь RAG-pipeline без Telegram: текстовый файл .txt извлекается, разбивается структурным чанкингом (границы абзацев и заголовков, цель ~900 символов, overlap ~150, параметры в конфиг), чанки получают эмбеддинги модели bge-m3 (1024) через новый порт эмбеддингов в inference-слое и адаптер Ollama (/api/embed, батчи), складываются в rag-БД — documents → chunks → виртуальная таблица векторов vec0, с владельцем и привязкой к документу. Поиск по корпусу владельца возвращает top-K (K=5, переопрос с запасом, косинус) с источниками; ниже конфигурируемого порога близости — явное «ничего не найдено». Повторная индексация того же имени заменяет документ атомарно. Тикет несёт с собой зависимости (sqlite-vec, pypdf, python-docx), настройки и env.example.

## Comments

- Реализация: `src/bot/rag/` (extract/chunking/store/service), порт `EmbeddingProvider` + `OllamaEmbeddingProvider` (`/api/embed`, батчи) в inference-слое; rag-БД — `.data/rag.db`, схема только миграциями alembic (`alembic.ini` секция `[rag]`, ревизия создана `uv run alembic -n rag revision --autogenerate`, vec0 — `op.execute` внутри ревизии; правило закреплено в AGENTS.md).
- sqlite-vec 0.1.9: `distance_metric=cosine`, переопрос k = top_k × overfetch → join-фильтр по владельцу → top-K; similarity = 1 − distance.
- Тесты: unit (чанкинг, извлечение, хранилище, сервис, адаптер, настройки) + живой smoke `tests/integration/test_rag_smoke.py` против bge-m3 (пропуск без сервера/модели).
- Модель эмбеддингов не метрится существующими декораторами (это не `InferenceProvider`); учёт поиска как инструмента — тикет 04.
