# 06: PDF и DOCX — парсинг и страницы в источнике (бонус +1)

**What to build:** пользователь загружает .pdf или .docx — тот же путь до «Документ готов», что и для .txt: извлечение текста библиотечными парсерами (pypdf, python-docx), структурный чанкинг с привязкой чанка PDF к странице. Ответы по PDF несут точный источник: «Источник: file.pdf, стр. 12», когда страница доступна. Повреждённые PDF и DOCX дают понятные сообщения, бот продолжает работать.

**Blocked by:** 03 (Загрузка документов в Telegram)

**Status:** ready-for-agent

- [ ] .pdf и .docx проходят путь загрузка → индексация → поиск end-to-end через бот
- [ ] Чанки PDF несут номер страницы; источник в ответе содержит страницу, когда она доступна; для DOCX — источник без страницы
- [ ] Повреждённый PDF/DOCX → понятное сообщение из списка ошибок задания, бот живёт
- [ ] Бинарные фикстуры PDF/DOCX коммитятся в тесты; unit-тесты извлечения для обоих форматов
- [ ] Неподдерживаемые расширения по-прежнему отклоняются понятной ошибкой
- [ ] Гейты зелёные: ty check, ruff check, ruff format --check, pytest
