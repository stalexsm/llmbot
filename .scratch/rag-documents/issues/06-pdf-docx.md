# 06: PDF и DOCX — парсинг и страницы в источнике (бонус +1)

**What to build:** пользователь загружает .pdf или .docx — тот же путь до «Документ готов», что и для .txt: извлечение текста библиотечными парсерами (pypdf, python-docx), структурный чанкинг с привязкой чанка PDF к странице. Ответы по PDF несут точный источник: «Источник: file.pdf, стр. 12», когда страница доступна. Повреждённые PDF и DOCX дают понятные сообщения, бот продолжает работать.

**Blocked by:** 03 (Загрузка документов в Telegram)

## Comments

- Реализация: извлечение переписано на страницы — `extract_pages(name, content) -> tuple[PageText, ...]` (`rag/extract.py`): PDF через pypdf отдаёт по `PageText` на непустую страницу с номером с единицы, DOCX через python-docx — один блок абзацев без страницы, причём встроенные стили «Heading N» превращаются в «#»-разметку Markdown и структурный чанкинг режет DOCX по заголовкам, как .md. Новый шов `chunk_pages(pages, …) -> tuple[Chunk, ...]` (`rag/chunking.py`): каждая страница чанкуется независимо, чанк не смешивает соседние страницы — Источник точен до страницы; `position` сквозной. `RagService` гоняет лимит текста по сумме страниц и отдаёт чанки с страницами в store/эмбеддинги.
- Повреждённые файлы: сырые исключения парсеров (у pypdf — зоопарк, у python-docx — ошибки zip-контейнера) гасятся на границе rag-слоя в новое прикладное `CorruptedDocumentError`; Telegram-хендлер отвечает «файл повреждён или защищён паролем», бот живёт. Пустой документ (пустой .txt, сканированный PDF без текста, DOCX без абзацев) — прежнее `EmptyDocumentError`.
- Страница в Источнике проведена по готовой с тикета 02 цепочке `chunks.page` (колонка была в ревизии 0001 изначально) → `SearchHit.page` → «Источник: handbook.pdf, страница 2» в tool-ответе; системный промпт уже требовал указывать страницу. Схема БД не менялась — миграций нет.
- Фикстуры: `tests/unit/rag/fixtures/sample.pdf` (3 страницы с различимым текстом) и `sample.docx` (Heading 1/2 + абзацы) коммитятся; битые файлы — мусорные байты и обрезанная фикстура, пустые — генерируются на месте (pypdf/python-docx).
- E2E: юнит с настоящими DocumentService+RagService (фейковые эмбеддинги, реальный SQLite, замоканный Telegram) — .pdf и .docx доходят до «Документ готов» и остаются в корпусе владельца; страница в источнике — на шве инструмента (`test_search_tool.py`).
- Гейты: `uv run ty check`, `uv run ruff check .`, `uv run ruff format --check .`, `uv run pytest` — 452 passed.
- Ревью (две оси параллельно): P1 «переписана применённая миграция» — ложное срабатывание (миграция не менялась, `page` в 0001 с тикета 02). Принято и исправлено: `chunk_pages` возвращает кортеж (согласованность новых швов), убран лишний `or ""`, добавлен end-to-end тест через бот-слой. Отклонено с обоснованием: Data Clumps «ChunkingParams» (форма существовала до тикета, вынесение — объём 02), дублирующий `document_kind` в сервисе (дешёвый dict-lookup в двух осмысленных контекстах), потеря текста таблиц DOCX (спека требует извлечение библиотечным парсером; таблицы — отдельный тикет).
