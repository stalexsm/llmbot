# 01: Чат-сессии переезжают на SQLite

**What to build:** история диалогов одного чата переживает рестарт процесса, хранясь в SQLite — отдельный файл chats-БД рядом с будущей rag-БД. Контракт хранилища сессий (прочитать / дописать / сбросить) не меняется: подменяется только реализация, application-слой подмены не замечает. Хранимое не меняется: только диалог «пользователь ↔ финальный ответ», без системных ролей и tool-обмена. Решение зафиксировано в ADR-0003.

**Blocked by:** None (можно начинать сразу)

**Status:** done

- [x] Контракт хранилища сессий не изменился; существующие unit-тесты сессий проходят с временным файлом БД — это же проверка заявления ADR-0003
- [x] Появляется временная метка сообщения, которой в JSONL не было
- [x] Команда /new удаляет сообщения чата; окно истории читается корректно (последние N по убыванию id)
- [x] История переживает рестарт процесса; старые JSONL-файлы не импортируются и не трогаются
- [x] Сбой БД маппится в существующее прикладное исключение: пользователь получает заглушку, работа бота не рвётся
- [x] Метрики остаются в append-only JSONL; описание чат-сессий в docs/architecture.md и упоминание JSONL-сессии в ADR-0001 обновлены при реализации
- [x] stdlib sqlite3 синхронно, без aiosqlite; гейты зелёные: ty check, ruff check, ruff format --check, pytest
