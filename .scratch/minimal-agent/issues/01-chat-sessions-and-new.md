# 01: Чат-сессии и /new

**What to build:** Бот помнит контекст диалога: каждое сообщение пользователя обрабатывается с подмешанной историей его чат-сессии (единый длинный контекст), а не как независимый запрос. История хранится на диске в формате JSONL (один файл на чат, append-only, каталог данных исключён из git), переживает перезапуск процесса. При превышении окна истории (по умолчанию 20 сообщений, настраивается) берутся последние сообщения; срез смещается так, чтобы пара «вызов инструмента → результат» (когда появится) не оказалась разорванной. Команда /new end-to-end: обрезает сессию и подтверждает новым чатом. Параллельные сообщения одного чата обрабатываются последовательно (блокировка на чат), история остаётся консистентной.

**Blocked by:** None (can start immediately)

**Status:** ready-for-agent

- [ ] Второе сообщение в том же чате видит первое (модель отвечает с учётом контекста)
- [ ] История переживает перезапуск процесса (читается с диска при следующем сообщении)
- [ ] При превышении окна берутся последние N сообщений
- [ ] Срез не разрывает пару «вызов инструмента → результат» (запрос к модели остаётся валидным)
- [ ] /new очищает сессию; следующий вопрос модели не видит старого контекста
- [ ] Два быстрых сообщения подряд обрабатываются строго последовательно
- [ ] Системные сообщения не пишутся в файл сессии (собираются заново при запросе)
- [ ] Юнит-тесты: append/чтение, окно, срез по границе пар, обрезка при /new; тесты хендлера /new с подменённым сервисом
