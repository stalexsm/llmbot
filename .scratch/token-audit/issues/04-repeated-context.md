# 04: Метрика повторно передаваемого контекста

**What to build:** для каждого вызова модели считается, сколько его промпта модель уже видела: префиксное пересечение с предыдущим запросом того же Запуска агента, по символам, откалиброванное точным счётчиком токенов промпта. Повторные токены попадают в `llm_call`, агрегат и доля (cache hit rate) — в `run`. Прямых данных кэша Ollama не существует — это честная прокси-метрика.

**Blocked by:** 02.

**Status:** done

- [x] Два последовательных запроса с общим префиксом дают повторные токены > 0, без общего префикса — 0 (тест на скриптованном провайдере)
- [x] Пересечение считается по спискам сообщений, без обращения к содержимому ради записи (в событие идут только числа)
- [x] В `run` появляется суммарный повторный контекст и его доля
- [x] Все четыре гейта зелёные

## Comments

- Реализовано агентом на ветке `token-audit`. Новое: `src/bot/metrics/repeat.py` — чистый шов `prompt_chars` / `repeated_prefix_chars` (общий префикс списков сообщений; размер сообщения = контент + аргументы tool-вызовов). `MeteredInferenceProvider` передаёт сообщения запроса и флаг `reached_model` в `RunMetricsCollector.record_llm_call` (обязательные kw); коллектор хранит сообщения последнего дошедшего до модели запроса запуска в аккумуляторе, состояние сбрасывается в `finish_run`. Калибровка: `round(prompt_tokens * repeated_chars / total_chars)`; без `prompt_tokens` от провайдера — `None`, пустой промпт — 0. В `llm_call` — `repeated_context_tokens`; в `run` — `repeated_context_tokens` и `repeated_context_ratio` (доля в промпт-токенах, округление до 4 знаков; proxy cache hit rate). Тесты: `tests/unit/metrics/test_repeat.py` (6), `test_collector.py` (+6), `test_provider.py` (+4, включая скриптованный провайдер и непересекающиеся запросы), `test_recorder.py` расширен allowlist'ом ключей. Первый вызов запуска и первый вызов нового `request_id` дают 0 — состояние не течёт между запусками. Гейты: ty / ruff check / ruff format --check / pytest (247 passed) — зелёные. `docs/architecture.md` (секция метрик) дополнен.
- Ревью Standards/Spec (параллельные сабагенты): блокеров нет. Принято по ревью (P2, Spec): промпт неудачного вызова больше не запоминается как «уже виденный» — в `record_llm_call` добавлен `reached_model`, обновление `last_messages` только для дошедших до модели вызовов; кейс «два запроса без общего префикса — 0» покрыт на скриптованном провайдере (`test_disjoint_requests_on_scripted_provider_repeat_zero`). Отложено (P2, вне тикета 04): неиспользуемые поля длительностей `InferenceUsage` (появились в 01, потребятся отчётом 05), композитная строка `exec:<класс>` в `tool_call` (03), дублирование `_sum_int`/`_sum_float` и формы тайминг-декораторов (02).
