# 07: Умная обрезка exec-вывода

**What to build:** вместо простого среза по лимиту символов вывод exec чистится: снимаются ANSI/прогресс-шум, сохраняются голова и хвост в пределах прежнего лимита — итоги и ошибки в конце выводов не теряются. Модель видит чистый вывод с понятным маркером обрезки.

**Blocked by:** None (can start immediately).

**Status:** done

- [x] ANSI-коды и прогресс-шум удаляются (тест на реальной команде с шумным выводом)
- [x] Голова и хвост вывода сохранены, середина сжимается, лимит символов соблюдён
- [x] Маркер обрезки присутствует в выводе и понятен модели
- [x] Поведение управляется прежней настройкой лимита; новые переменные не плодятся
- [x] Все четыре гейта зелёные

## Comments

- Реализовано в `src/bot/agent/output.py`: `clean_output` (ANSI/OSC/CSI, кадры `\r`, backspace, спиннеры) и `truncate_middle` (голова+хвост до границы строк, маркер `…[середина вывода обрезана: пропущено N символов]`). Врезано в `ExecTool` (`_decode_and_clean` перед сборкой текста); настройка прежняя — `AGENT_EXEC_MAX_OUTPUT_CHARS`, новых переменных нет. Поведение описано в `docs/runtime.md`.
- Ревью (две оси, параллельные саб-агенты): жёстких нарушений нет; правки по находкам P2 — `_LINE_WINDOW` вместо магических `200`, `_limited_result` вместо трёх повторов `ToolResult(truncate_middle(…))`, `_CONTROL_RE` дополнен `\r`/C1 + тест на обрывочный ESC, ограничение CSI-перерисовки без `\r` задокументировано в докстринге, `env.example` и README синхронизированы с runtime-докой.
